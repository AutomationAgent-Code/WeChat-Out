# Windows 微信本地数据库读取路径

## 路由

按风险从低到高选择：

1. 用户已提供已解密 SQLite：直接做完整性和 Schema 检查后读取。
2. 用户提供的是加密数据库副本和本人账户密钥：在独立输出目录解密并验证，原文件保持只读。
3. 用户选择的兼容工具能从当前已登录的本人账户取得密钥：让用户完成必要登录，密钥不回显、不上传，取得后立即验证数据库并清理内存。
4. 第三方读取工具仅在其明确支持当前微信版本和数据库参数时使用。
5. 新版本适配属于开发任务：先收集版本、模块哈希、数据库头和失败日志；不得直接在主账户数据上反复试写。

## 常见数据库形态

- 联系人库：`db_storage\contact\contact.db`
- 消息库：`db_storage\message\message_0.db`（账户可能有多个分片）
- 标签成员可能位于联系人 `extra_buffer` 的 `label_list` 中。
- 单聊消息表可能以 `Msg_<联系人标识的 MD5>` 命名。
- 文本可能使用 zstd 压缩；解析失败时保留类型信息，不把二进制猜成文本。

这些名称只用于结构发现，不保证适用于所有微信版本。导出前检查 `sqlite_master`、实际字段、分片数量和内容编码。

## 一致性检查

- 可读打开数据库并检查 `PRAGMA quick_check`。
- 确认联系人表、发送者映射表和消息表存在。
- 对所有 `message_*.db` 建立清单，避免只导出第一个分片。
- 比较数据库最大 `create_time` 与用户期望的最新聊天日期。
- CSV 使用 UTF-8 BOM，避免 Excel 打开中文乱码。

## 读取流程示例

```powershell
python '<项目目录>\scripts\decrypt_sqlcipher.py' `
  --protected-key '<当前用户保护的密钥文件>' `
  --source '<加密数据库副本>' `
  --output '<解密数据库输出>'
```

解密参数必须以当前数据库实际页面参数和 HMAC 验证结果为准，不能只看到 SQLite 头就宣称成功。

```powershell
python '<项目目录>\scripts\read_chats.py' `
  --contact-db '<解密后的联系人库>' `
  --message-dir '<解密后的消息分片目录>' `
  --output '<聊天记录.jsonl>'
```

示例中的路径均为占位符。读取器应枚举所有消息分片，按稳定消息 ID 去重，并保留无法解析消息的类型和原始标识。不得把个人路径、账户标识或标签编号硬编码进公开脚本。
